# 古籍逐段多模型对齐方案

## 目标

华严经的现代白话必须尽量回挂到原文段落，允许：

- 一个现代段对应一个原文段；
- 多个现代段拆解同一个原文段；
- 一个现代段合并多个连续原文段；
- 现代译文有增释、遗漏或无法确认的情况。

字数比例只能用于缩小候选范围，不能生成最终对应关系。
由于原文常把一整段写得很紧凑、白话却拆成多个段，质量检查还会比较现代段与相邻原文段的术语锚点；若模型从 O6 错误推进到 O7，但 M 仍明显对应 O6，只能标为语义修正/待复核，不能通过“段号合法”这一项。

## 模型分工

| 层级 | 当前模型 | 作用 |
|---|---|---|
| 候选 | 本地 `qwen3:8b` | 全量逐段提出 O/M 对应，保存原始 JSON |
| 独立复核 | 本地 `gemma4:31b` | 对候选进行独立逐段判断，处理术语和边界 |
| 低置信裁决 | Gemini 2.5 Pro 或 3.1 Pro | 只处理本地模型冲突、越界或覆盖不足的窗口 |
| 最终确认 | 人工 | 确认段边界、遗漏和多对多关系后才进入 verified |

当前代码入口是 `align_canon_models.py`。每个任务按最多 80 个现代段分窗口，避免长 JSON 截断；每个窗口保留同一品/卷的原文段上下文。

## 项目自有翻译：一原文小段一译文

网页白话只能作为语义参考，不能继续作为项目译文的边界。项目自有翻译使用
`translate_huayan_segments.py`：每次请求只提交一个原文单元，返回一个
`translation`，并记录 `original_segment_index`、`unit_index`、模型、提示版本和复核状态。
原文超过长度阈值时，先沿换行和句末标点拆成小单元；多个小单元仍可挂在同一个原文段下，
不会把它们错误挂到下一个原文段。

模型提示明确禁止只做繁简转换，并允许读取已经对齐的洪启嵩白话作为语义参考；参考文本不进入
最终译文，也不改变本次原文单元边界。生成层写入
`huayan_t0279_generated_layers.jsonl`，默认是“待人工复核”，与网页白话分开显示。

```bash
python3 translate_huayan_segments.py \
  --chapter 1 --start-segment 5 --limit 2 \
  --model qwen3:30b-a3b --materialize
```

## 结果状态

统一 `review_status`（见 `numerology/corpus_quality.py`）：

| review_status | confidence 上限 | 含义 |
|---|---|---|
| `candidate` | low | 模型候选 / 历史层 / 缺 provenance |
| `model_agree` | medium | 双模型一致，仍待人工 |
| `human_verified` | high | 人工复核通过（唯一可标 high） |
| `rejected` | low | 人工驳回 |

历史文案映射：

- `已双模型一致` → `model_agree`（仍非 verified）
- `待人工复核：…` / `已对齐`（无 provenance）→ `candidate`
- 模型 materialize **永不**写 `human_verified`

每条结果保存模型名称、原始响应、证据短语、关系类型、置信度和耗时。只有带 `original_segment_indices` 的结果会进入逐段层；空映射仍保留在候选文件中，不能悄悄丢弃。

质量审计：

```bash
python3 normalize_corpus_layers.py   # 降级非法 high、补 provenance、规范化周易键
python3 reclassify_nde.py            # 按最新 phenomena.yaml 重分类
python3 audit_corpus_mapping.py      # 写出 data/audits/corpus_mapping_latest.json
```

页面 `/quality` 顶部展示三域映射审计摘要。

## 人工复核写回

古籍阅读页每条挂接的现代白话/现代释译下方有「通过 / 驳回 / 重置」：

- 写入 `data/processed/canon/reviews/<book>_reviews.jsonl`（追加，不改生成层）
- `human_verified` 才允许 `confidence=high`
- 译文文本变更后指纹不匹配 → 自动降为 candidate（复核过期）
- 重跑 translate / align 不会冲掉 sidecar 复核记录

```bash
# 华严缺段（阅读层缺口）
python3 translate_huayan_segments.py --list-missing
python3 translate_huayan_segments.py --fill-layer-gaps --limit 20 --materialize
# 默认合并写入 generated_layers；不要加 --replace-layer 除非确认要整文件覆盖

# 人工复核队列
python3 list_review_queue.py --book huayan_t0279 --status candidate --limit 20
# 网页：/quality/review?book=huayan_t0279&status=candidate
```

## 句句对应（推荐主路径，不要先盲训模型）

目标：每一句原文有明确白话，阅读页 `pairs` 悬停高亮。

| 方案 | 何时用 | 说明 |
|---|---|---|
| **强制句对齐 DP** | **默认** | `align_huayan_sentences`：有段级 aligned 白话则在段内切句 DP；否则章窗口单调 DP |
| 本地 Ollama 裁决 | 低分句 | `--ollama --model qwen3:8b`，只在候选窗内选号，不整章自由生成 |
| 一原文单元一译 | 无参考白话时 | `translate_huayan_segments` |
| Fine-tune / 训练 | 金标够多之后 | 用本脚本 + 人工 verified 的 pairs 做 LoRA；**不要先训再对齐** |

```bash
# 第 1 章句句对齐并合并写入（约半分钟）
python3 -m scripts.canon.align_huayan_sentences --chapter 1 --materialize

# 低分句再用本地模型重判
python3 -m scripts.canon.align_huayan_sentences --chapter 1 --ollama --model qwen3:8b --materialize
```

实现：`numerology/huayan_sentence_align.py`（`force-align-v1`）。阅读页会优先挂该层，并过滤网页垃圾与伪繁简。

## 可复现命令

```bash
# 先处理一个任务，检查输出
python3 align_canon_models.py \
  --book huayan_t0279 \
  --task-id huayan:17:16:0013 \
  --models qwen3:8b gemma4:31b \
  --materialize

# 本地候选与独立复核冲突时，再调用 Gemini
python3 align_canon_models.py \
  --book huayan_t0279 \
  --models qwen3:8b gemma4:31b \
  --online-review --online-model gemini-2.5-pro \
  --materialize
```

页面优先加载 `huayan_t0279_aligned_layers.jsonl`；尚未完成的卷/品继续显示原来的现代译文区块，不会因局部任务完成而把整本书隐藏。

## 回归检查

此前测试只检查 JSON 可解析、段号存在和映射单调，没有检查“长原文被白话拆成多个段”的语义关系；因此错误的一对一推进曾经通过。这属于测试设计缺陷。

现在加入语义锚点回归用例：当 M1、M2 都解释 O6，而旧映射把 M2 推进到 O7 时，必须修回 `M2 → O6`，并允许多个现代段共同挂到同一原文段。当前测试结果为 `60 passed`。
