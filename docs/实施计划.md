# 实施计划

> 研究设计、数据源评估、古籍综述、统计方法与风险清单见 [研究综述与数据源.md](研究综述与数据源.md)。
> 本文档只讲**工程实施**：代码结构、分阶段任务、验收命令。
>
> 定位：严谨假设检验（预注册 → 协变量控制 → FDR → 效应量）；古籍层多流派并行对比。

## 代码结构设计

### 存储分层：SQLite 存原始，Parquet 做分析

统计分析要反复全表扫描 + 宽表 join，SQLite 不适合。分层：

- **SQLite**（`data/numerology.db`）—— 原始采集数据 + 排盘结果，唯一事实来源
- **Parquet**（`data/features/*.parquet`）—— 由 SQLite 物化出的特征矩阵，每流派一个文件，分析层只读它

上游 source-native 文件不直接改写：

- `data/raw/cbdb/<release>/` 保存 CBDB 官方 SQLite 和压缩包；
- `data/raw/adb/<release>/` 保存 ADB XML sample 或许可范围内的数据；
- `data/raw/wikidata/<snapshot>/` 保存按快照分批的 JSONL 结果。

`import_cbdb.py` 已将 CBDB 2026-07-25 版本的人物基本信息、出生事实和死亡事实导入 `numerology.db`；原始 CBDB SQLite 仍保持只读。详细目录与字段见 [数据下载与存储.md](数据下载与存储.md)。

新增依赖：`pyarrow`、`statsmodels`、`lifelines`（生存分析，可选）、`pyyaml`。

### 古籍规则引擎：规则是数据，代码只是解释器

**关键约束**：所有古籍规则写在 YAML 里，每条规则必须带 `source`（书名 + 篇名）和 `quote`（原文），
代码只做解释执行。这样规则可审计、可复现、换流派不用改代码，且预注册假设与实现天然绑定。

```
numerology/canon/
├── schools/
│   ├── ziping.yaml          # 子平真诠（原著月令派）：取格三级回退链 + 成败/救应
│   ├── xuleiwu.yaml         # 徐乐吾评注派：扶抑/病药/专旺/通关（与上者不兼容，故独立）
│   ├── ditiansui.yaml       # 滴天髓：气势/调候/寒暖燥湿/通关/体用
│   └── qiongtong.yaml       # 穷通宝鉴：月令×日主 调候用神表（120 格）
├── tables/
│   ├── canggan.yaml         # 藏干（本气/中气/余气 + 各家权重）
│   ├── xingchonghehui.yaml  # 刑冲合会
│   ├── shensha.yaml         # 常用神煞（华盖/空亡/魁罡/羊刃/文昌/天医…）
│   └── dishi.yaml           # 十二长生
├── hypotheses.yaml          # 预注册假设清单（锁定后不可改）
└── engine.py                # 规则解释器
```

规则表**必须人工从原文录入**，不能让模型自动生成 —— 操作化定义的忠实性是整个研究可信度的基础。

### 分析层

`numerology/analysis/`（目前空目录）：

| 文件 | 职责 |
|---|---|
| `baseline.py` | 经验基线、匹配对照组抽样（记录 seed）、标签置换 |
| `models.py` | logistic（分类结果）、Cox（寿命，处理左截断） |
| `inference.py` | FDR 校正、效应量 + CI、最小实质效应量判定 |
| `robustness.py` | 跨排盘变体、Rodden 分层、排除边界样本、排除整点堆积、南北半球分层 |
| `controls.py` | 负对照（打乱日期）、正对照 A（太阳星座）、正对照 B（出生月效应） |
| `report.py` | 生成 Markdown 报告 |

### 排盘变体表

排盘的流派分歧点变成一等公民的配置维度，而不是硬编码：

- `true_solar_time`: on / off
- `sect`: 1 / 2（晚子时归次日 / 归当日 → 影响日柱即日主）
- `canggan_weights`: equal / classic
- `year_boundary`: 立春 / 正月初一（`lunar_python` 已有 `getYearInGanZhiByLiChun`）

`bazi` 表主键从 `UNIQUE(person_id)` 改为 `UNIQUE(person_id, config_id)`，新增 `bazi_configs` 表，
并记录 `engine_version`。**主分析锁定一个配置，其余全部作为稳健性检验** ——
一个"发现"若在换 `sect` 后消失，它就不是发现。

## 分阶段任务

### P0 — 数据修复与补采（阻塞一切后续工作）

对应综述 1.3 的六条问题。

1. **接线现有工作树改动**
   - `schema.py` 加列：`tz_meridian`、`tz_abbr`、`time_type`、`time_accuracy`、`time_unknown`、
     `sun_degmin`、`moon_degmin`、`asc_degmin`
   - `pipeline.py:210` 的 `calculate_bazi()` 调用传入 `lon` / `tz_meridian_lon` /
     `true_solar_time` / `sect` / `canggan_weights`（这些参数已在 `engines/bazi.py` 实现但无人调用）
   - 加 SQLite migration 机制（目前 `init_db()` 只有 `CREATE TABLE IF NOT EXISTS`，加列会静默失败）

2. **重采分类**——改用 MediaWiki `prop=categories`
   - 在 `fetch_pages_content()`（`adb.py:337`）的 API 调用加
     `"prop": "revisions|categories", "cllimit": "max"`，一次请求同时取 wikitext 与真实分类
   - **先用 3 个已知条目（Presley / Einstein / 一个 Military 条目）验证能取到 `Vocation : *`，
     再跑全量**。ADB 有反爬，须走 collector 自带的 requests + UA
   - 成本：1478 请求 × 2s ≈ 50 分钟，建议后台跑

3. **分类结构化**——`categories` 表加 `domain` / `field` / `leaf`（按 ` : ` 拆分），
   替换 `_classify_category()`（`pipeline.py:39`，它只认 "occupation"/"vocation" 字面，
   对 ADB 实际格式全部落到 `other`）

4. **回填死亡日期**——从 `events` 表 `event_code LIKE 'Death%'` 回填 `persons.death_date` /
   `death_year` / `cause_of_death`（35,576 人），计算 `lifespan_days`

5. **清洗**——`birth_country` 规范化（州名 → 国家 + 新增 `birth_region`）；剔除 261 条脏出生年；
   重算全库 lat/lon（度分秒 bug 已修，需重跑）

6. **标注边界样本**——`time_on_boundary`（分钟数落在时柱边界 ±15 分钟内）、
   `time_rounded`（分钟数为 0 或 30）

补充完成项：ADB 原始坐标字段已回源修复，跨日期变更线的经度已做环绕归一化；
`events_normalized` 已将部分日期转换为闭区间，原始 `events` 表保留不变；
`quality_audit_runs` / `data_quality_flags` 已支持按审计版本保存逐条质量标签，原始记录不被删除。

  - `_parse_meridian` 两种格式（`h5w` → -75.0、`m10e0` → 10.0、`h5e30` → 82.5）

  - `sect` 1/2 在 23:30 出生时给出不同日柱

### P2 — 事件标准化

- `events_normalized` 表：`event_type` / `event_subtype` / `date_start` / `date_end` /
  `date_precision` / `quality_status` / `quality_flags`
- **只有年份的事件存成区间，不能补成某一天**（现有 `events.event_date` 里有 `00` 占位）
- 优先处理相对客观的事件：死亡、结婚、离婚、工作变化、获奖、迁移、重大疾病

### P2.5 — 古籍校勘与规则模板定稿（P3 的前置，可与 P0 数据任务并行）

进入 P3 写任何 school YAML 之前必须完成，否则提取错误会在 P4 预注册锁定后被永久固化。

1. **文本分层标注**——当前语料多为现代评注本（如 `ziping_zhenquan_online.txt` 实为徐乐吾
   《子平真诠评注》），每段提取必须标注 `text_layer: 原文 | 评注 | 现代白话`。
   已知错误：《古籍逻辑提取初稿》曾把徐注"五用神"（扶抑/病药/调候/专旺/通关）记在沈孝瞻
   原著名下——原著取用是"用神专求月令……财官印食顺用、煞伤劫刃逆用"的月令取格逻辑，
   与徐注扶抑逻辑不兼容（对应 `ziping.yaml` 与 `xuleiwu.yaml` 两个独立流派）。
2. **规则 YAML schema 定稿**——在写第一条规则前锁定字段：`rule_id` / `school` /
   `source_book` / `edition`（版本）/ `source_section`（篇名，不用网页版章节号或 PDF 页码）/
   `quote`（原文引文，作为锚定与审计依据）/ `text_layer` / `if` / `then` / `candidate_y` /
   `operational`（是否已可机器执行；"要重新判断""倾向于"类措辞标 `false`）/ `rule_status`。
3. **排盘输入规范补齐**——统一输入必须含：性别（大运顺逆排依赖阳男阴女）、出生地点经纬度
   （真太阳时）、早晚子时归属（sect）、节气精确时刻（起运岁数）、历法转换。与 P1 的
   `bazi_configs` 对齐。
4. **扫描本抽样校勘**——对每本书抽取将进入 P4 假设清单的段落，与扫描页逐条核对；
   校勘结论回写 `rule_status: candidate → verified`。
5. **验收**——手工验算 5–10 个《子平真诠》原书经典命例，取格结果与原书一致（与 P1 验收共用）。

### P3 — 古籍规则引擎（多流派）

- `canon/engine.py` + 各 school YAML
- 子平取格三级回退链与成败四态判定见综述 3.2；`因成得败/因败得成` 实现为 override 层
- 每条规则输出携带 provenance，特征表保留 `rule_id`，任何统计结果都能反查原文
- 输出 `data/features/{ziping,xuleiwu,ditiansui,qiongtong}.parquet`

### P4 — 预注册假设清单（需人工审核锁定）

每条含：出处原文 → 特征操作化定义 → ADB 分类映射 → 预测方向。草案（**待审核**，
操作化的忠实性需人工判断，映射目标须查 [Help:Category](https://www.astro.com/astro-databank/Help:Category) 的官方定义）：

| 古籍断言 | 操作化 | 因变量 | 方向 |
|---|---|---|---|
| 伤官主才艺文华 | 伤官格 / 伤官透干 | `Vocation : Writers : *`、`Vocation : Entertain*` | 偏多 |
| 七杀、阳刃主武职凶暴 | 七杀格 / 羊刃格 | `Vocation : Military : *`、`Passions : Criminal Perpetrator` | 偏多 |
| 食神主寿 | 食神格且不见枭神 | 寿命（Cox） | HR < 1 |
| 印绶主文教 | 正印格 | `Vocation : Education : *`、`Vocation : Science : *` | 偏多 |
| 财格主商 | 正财 / 偏财格 | `Vocation : Business : *` | 偏多 |
| 华盖、空亡主僧道 | 华盖 / 日时空亡 | `Personal : Religion*` | 偏多 |

清单锁定后写入 `canon/hypotheses.yaml`，**单独 commit 并打 tag** 形成时间戳。
锁定后不得修改 —— 这是预注册的全部意义。

### P5 — 统计框架与对照实验

按综述第五节实现 `analysis/` 各模块。**执行顺序强制为：先跑负对照，通过后才跑正式分析。**

### P6 — 报告与前端

- 主报告：预注册假设逐条结论（效应量 + CI + q 值 + 各稳健性检验下是否存活）
- 对照实验结果单独成节 —— 这是读者判断可信度的依据
- `server.py`（194 行）加结果展示页；探索性发现明确标注「未预注册，仅供参考」

## 验收命令

### P0

```bash
# 1. 分类补采成功
sqlite3 data/numerology.db "SELECT domain, COUNT(DISTINCT person_id) FROM categories GROUP BY domain;"
# 期望：出现 Vocation / Traits / Diagnoses / Passions / Personal / Notable / Lifestyle / Family
sqlite3 data/numerology.db "SELECT COUNT(*) FROM categories WHERE domain='Vocation';"
# 期望：远大于 0
sqlite3 data/numerology.db "SELECT COUNT(*) FROM categories WHERE leaf='Fiction' AND field='Writers';"
# 期望：接近 ADB 官方的 3085

# 2. 死亡数据回填
sqlite3 data/numerology.db "SELECT COUNT(*) FROM persons WHERE death_year IS NOT NULL;"
# 期望：≈ 35576

# 3. 经纬度修复
sqlite3 data/numerology.db "SELECT COUNT(*) FROM persons WHERE ABS(birth_lat)>90 OR ABS(birth_lon)>180;"
# 期望：0

# 4. 脏出生年清除
sqlite3 data/numerology.db "SELECT source, COUNT(*) FROM persons WHERE (source='adb' AND (birth_year>2026 OR birth_year<1500)) OR (source='cbdb' AND (birth_year>2026 OR birth_year<-1000)) GROUP BY source;"
# 期望：只出现待人工回查的 ADB/CBDB 可疑年份，不把 CBDB 正常历史年份误删

# 5. 事件日期标准化
sqlite3 data/numerology.db "SELECT quality_status, COUNT(*) FROM events_normalized GROUP BY quality_status;"
# 期望：valid + warning，invalid 为 0

# 6. 逐条质量标签可追溯
python3 audit_data.py --persist --output data/audits/data_quality_YYYYMMDD.md
sqlite3 data/numerology.db "SELECT flag_code, severity, COUNT(*) FROM data_quality_flags WHERE audit_run_id=(SELECT MAX(id) FROM quality_audit_runs) GROUP BY flag_code, severity;"
# 期望：每条标签关联一个 audit_run_id，error 可直接排除，warning 可分层
```
