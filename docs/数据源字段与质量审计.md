# 数据源字段、缺失与可信度审计

更新日期：2026-07-31

## 结论

当前项目中的数据问题不是单一的“空值问题”，而是三类不同问题：

1. **格式错误**：例如经纬度越界、出生年份晚于当前年份、死亡早于出生。
2. **信息缺失**：例如 CBDB 大量人物没有出生年份，ADB 部分人物没有出生时刻。
3. **来源不确定性**：例如 CBDB 的历史年份可能是推定值，ADB 的事件日期可能只有年份。

三类问题不能用同一种方式处理。格式错误应修复或排除；信息缺失应保留精度标签；来源不确定性应进入分层和敏感性分析。

## 一、数据来源与字段说明

### 1. Astro-Databank（ADB）

ADB 是本项目的精确出生时间和现代生平事件来源。项目当前本地库有 73,877 条记录。

| 字段 | 含义 | 研究用途 | 主要风险 |
|---|---|---|---|
| `source_id` | ADB page ID | 稳定来源键 | 不等于人物的跨库统一 ID |
| `name` | 人物名称 | 实体识别 | 姓名格式不统一 |
| `gender` | M/F | 协变量、分层 | 有少量缺失或特殊性别情况 |
| `birth_date` | 出生日期 | 年/月/日排盘 | 日期可靠性由 Rodden 评级决定 |
| `birth_time` | 出生时间 | 时柱、四柱 | 3,384 人没有出生时间 |
| `birth_lat/lon` | 出生地点经纬度 | 真太阳时校正 | 当前有越界值，需重算 |
| `rodden_rating` | AA/A/B/C/DD/X/XX 等 | 数据质量分层 | 不是数值精度，不能简单当连续变量 |
| `categories` | 职业、事件、人物标签 | 结果变量候选 | 当前历史导入的分类质量不一致 |
| `events` | 婚姻、死亡、工作等事件 | 时间窗分析 | 日期常为 `YYYY-00-00` |

ADB 的 Rodden 评级是基于出生资料来源的质量分类。官方定义中，AA 通常来自出生证、出生记录等；A 通常是本人、亲属或相关人士提供；C/DD/X/XX 的可靠性和时刻完整度更低。[ADB DataSource](https://www.astro.com/astro-databank/Help%3ADataSource)、[ADB Rodden Rating](https://www.astro.com/astro-databank/Help%3ARR)

因此 ADB 主分析建议至少分为：

```text
AA/A：主分析
B：敏感性分析
C/DD/X/XX：探索性或排除
```

### 2. China Biographical Database（CBDB）

CBDB 是历史中国人物数据源。当前已导入 660,181 人物。

CBDB 的核心表是 `BIOG_MAIN`，当前版本主要字段包括：

| 字段 | 含义 | 当前处理 |
|---|---|---|
| `c_personid` | CBDB 人物 ID | 写入 `persons.source_id` |
| `c_name/c_name_chn` | 拉丁/中文姓名 | 中文名优先 |
| `c_surname/c_mingzi` | 姓与名 | 写入 `last_name/first_name` |
| `c_female` | 性别编码 | 0=M，1=F，空值=未知 |
| `c_birthyear` | 出生年份或推定年份 | 写入 `birth_facts.raw_year` |
| `c_by_month/c_by_day` | 出生月/日 | 只在存在时使用 |
| `c_by_range` | 出生年份范围码 | 原值保留，不解释成精确日期 |
| `c_deathyear` | 死亡年份或推定年份 | 写入 `death_facts.raw_year` |
| `c_death_age` | 记录中的死亡年龄 | 作为辅助一致性检查 |
| `c_index_year` | 分析用索引年份 | 不等于真实出生年份 |

CBDB 官方明确区分真实出生/死亡日期、活动年份区间、年号信息和分析用 `index year`；`index year` 是为了把人物定位到时间轴而生成的人工字段，不能直接当作出生年份。[CBDB Structure](https://cbdb.hsites.harvard.edu/structure-cbdb)

因此 CBDB 当前只导入人物事实，不自动生成八字。原因是：

- 绝大多数人物没有出生时辰；
- 出生年份可能是推定值；
- 传统纪年转西历后仍保留不确定性；
- 历史人物的月份和日期不一定具备适合现代历法排盘的精度。

### 3. Wikidata

Wikidata 计划作为公开、广覆盖的现代人物三柱对照源，目前还没有导入本地库。

| 属性 | 含义 | 存储要求 |
|---|---|---|
| `Q-ID` | 人物实体 ID | 作为 `source_id` |
| `P569` | 出生日期 | 必须同时读取时间精度和 qualifiers |
| `P570` | 死亡日期 | 保留精度和来源 |
| `P19` | 出生地 | 保留实体 ID，不只存文本 |
| `P106` | 职业 | 保留原始 Q-ID 和标签 |
| `P509` | 死亡原因 | 保留原始 Q-ID |
| reference | 声明来源 | 作为可信度信息 |

Wikidata 的年份精度可能在界面上表现为某年 1 月 1 日，但不能据此认为人物出生于 1 月 1 日；官方日期说明明确要求保留时间精度并识别由数据库转换产生的占位日期。[Wikidata P569](https://www.wikidata.org/wiki/Property:P569)、[Wikidata Dates](https://www.wikidata.org/wiki/Help%3ADates/en)

## 二、当前本地缺失情况

审计命令：

```bash
python3 audit_data.py --output data/audits/data_quality_YYYYMMDD.md
# 同时把每条问题写入 SQLite，保留本次审计版本
python3 audit_data.py --persist --output data/audits/data_quality_YYYYMMDD.md
```

截至 2026-07-31：

| 来源 | 人物数 | 缺少性别 | 缺少出生年 | 缺少出生时刻 | 缺少死亡年 |
|---|---:|---:|---:|---:|---:|
| ADB | 73,877 | 2,937 | 0 | 3,384 | 73,877 |
| CBDB | 660,181 | 24,244 | 600,330 | 660,181 | 588,899 |

这些缺失并不全部表示错误：

- ADB 缺少时刻的记录不能进入四柱主分析，但可以进入三柱分析。
- CBDB 缺少出生年份的人物可以研究社会网络或文本关系，但不能进入出生日期研究。
- ADB 缺少死亡年份不影响出生/职业研究，但不能进入寿命分析。
- 缺少性别的数据可以保留，但不能用于需要性别控制的模型。

审计结果：

| 非人物条目 | 9 | 排除人物分析，原始记录保留 |
| 出生年份晚于 2026 | 5 | 回查来源；确认前排除 |
| 死亡早于出生 | 5 | 回查来源和纪年；确认前排除 |
| 推导寿命超过 120 年 | 3 | 作为可疑记录，不直接删除 |

| CBDB 人名为“未详” | 1 | 不用于人物实体对齐 |
| 事件日期含 `00` 月/日 | 40,063 | 已转入 `events_normalized`，不得当精确日期使用 |

坐标修复脚本从 ADB page ID 回源读取原始字符串，并将原始值保存到
`birth_lat_raw` / `birth_lon_raw`；因此修复不是根据越界数值反推。当前 ADB 2,389 条曾经异常的记录均已回源成功，审计后的越界数为 0。

事件标准化结果：

- 总事件：103,669 条；
- 日级精度：63,606 条；
- 月级精度：6,916 条；
- 年级精度：33,147 条；
- 无效日期：0 条。

其中 ADB 经纬度越界很可能与度分秒解析有关，属于可以修复的格式问题；事件中的 `YYYY-00-00` 不是格式错误，而是精度不足，需要转换成时间区间。

逐条标签的首次本地运行结果（`audit_run_id=1`）为 43,734 条：

- `warning`：43,724 条，主要是部分事件日期、ADB 缺少出生时刻和 ADB 年份范围问题；
- `error`：10 条，其中出生年份晚于当前年份 5 条、死亡早于出生 5 条；
- 标签均能通过 `audit_run_id` 追溯到本次规则版本，当前没有孤立标签。

## 四、不可置信数据的分级规则

### `error`：不能直接进入正式分析

- 出生年份晚于当前年份；
- 死亡年份早于出生年份；
- 经纬度越界；
- 出生小时或分钟越界；
- 事件日期不符合基本格式；
- 八字柱不是两个干支字符；
- 来源记录没有规范化人物映射。

### `warning`：保留，但必须带质量标签

- 出生年份缺失；
- 出生时间缺失；
- 只有年份或月份；
- ADB 评级为 C、DD、X、XX；
- CBDB 年份由年号或活动范围推定；
- 事件日期含 `00`；
- 人物姓名为“未详”；
- 可能存在名人/职业选择偏差。

### `info`：研究设计中需要控制

- 来源、出生年代、性别、地区；
- ADB 的记录完整度；
- Wikidata 的 reference 数量和 rank；
- CBDB 的朝代和历史时期；
- 是否使用真实太阳时、子时换日和不同藏干权重。

## 五、不可置信数据如何处理

不建议直接删除。当前项目将“汇总报告”和“逐条标签”分开保存：

- `quality_audit_runs`：记录规则版本、审计时间、当前年份和本次标签数量。
- `data_quality_flags`：记录具体实体类型、实体 ID、问题代码、级别和回查字段。

运行 `--persist` 后可以直接查询：

```sql
-- 最近一次审计中，哪些人物不能进入正式分析？
SELECT f.entity_id, p.name, f.flag_code, f.severity, f.details_json
FROM data_quality_flags f
JOIN quality_audit_runs r ON r.id = f.audit_run_id
JOIN persons p ON p.id = f.entity_id
WHERE r.id = (SELECT MAX(id) FROM quality_audit_runs)
  AND f.entity_type = 'person'
  AND f.severity = 'error';

-- 按规则统计最近一次审计结果
SELECT f.flag_code, f.severity, COUNT(*) AS n
FROM data_quality_flags f
WHERE f.audit_run_id = (SELECT MAX(id) FROM quality_audit_runs)
GROUP BY f.flag_code, f.severity
ORDER BY n DESC;
```

每次审计都会产生新运行版本，不覆盖历史标签；因此可以比较修复前后的错误数量。标签本身不修改原始人物、事件和来源记录。

## Web 查看

项目已有本地 Flask 查看页。先生成逐条标签，再启动服务：

```bash
python3 audit_data.py --persist
python3 server.py
```

浏览器打开 <http://127.0.0.1:8898/quality>，可以查看审计版本、按“错误”/“警告”、实体类型和规则筛选，并点击人物进入详情页。页面只显示中文标签，内部规则代码仅作为筛选值和悬停提示保留。首页和人物详情页也会显示最近一次质量审计摘要。端口可用环境变量修改，例如 `NUMEROLOGY_PORT=9000 python3 server.py`。

对分析层仍推荐保存以下字段：

```text
quality_status       # valid / warning / invalid
quality_flags        # JSON 数组
quality_checked_at
quality_rule_version
```

示例：

```json
{
  "quality_status": "warning",
  "quality_flags": [
    "birth_year_precision_year",
    "death_year_inferred",
    "cbdb_index_year_not_birth_year"
  ],
  "quality_rule_version": "2026-07-31"
}
```

最终分析时：

- `invalid`：排除；
- `warning`：主分析排除或分层，敏感性分析保留；
- `valid`：进入主分析；
- 任何排除都必须报告数量和规则。
