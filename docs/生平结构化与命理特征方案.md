# 生平结构化与命理特征方案

更新日期：2026-07-31

## 一、当前人物库不是单一数据源

人物表通过 `persons.source` 区分来源，当前本地数据为：

| 来源 | 当前数量 | 主要用途 | 出生时间情况 |
|---|---:|---|---|
| ADB | 73,877 | 现代人物、出生时间、生平事件 | 部分人物有分钟级时间和 Rodden 评级 |
| CBDB | 660,181 | 历史人物、社会关系和官职史 | 基本没有出生时辰，日期常为年份或推定区间 |
| Wikidata | 0 | 公开数据对照和实体补充 | 计划导入，通常只有日/月/年精度 |

人物列表应显示来源并支持按来源筛选。来源不是一个可以忽略的标签，而是分析设计中的核心协变量：ADB 与 CBDB 的时代、人物选择、日期精度和记录机制都不同，不能直接混合为一个样本后解释。

## 二、生平数据可以怎样结构化

当前已经有两类可用信息：

1. `events`：事件代码、日期、地点、备注；已经转换到 `events_normalized`，保留日期区间和日期精度。
2. `categories`：职业、兴趣、疾病、关系等标签；需要继续按 ADB 的分类层级整理。

传记原文还可以提取为统一的 `life_facts` / `biography_facts`，但原文必须保留，抽取结果不能覆盖原文。建议每条事实至少包含：

| 字段 | 作用 |
|---|---|
| `person_id` | 规范化人物 ID |
| `fact_type` | 婚姻、职业、教育、迁移、疾病、获奖、犯罪、死亡等 |
| `date_start/date_end` | 事实发生区间，不把年份强行变成某一天 |
| `date_precision` | 年、月、日或区间 |
| `value_text` | 事实内容，如职位、疾病、奖项 |
| `place` | 地点，保留原文和规范化地点 |
| `source_record_id` | 回溯到 ADB/CBDB/Wikidata 来源 |
| `source_span` | 原文证据片段或字符位置 |
| `extraction_method` | 规则、人工、模型 |
| `extractor_version` | 抽取器版本 |
| `confidence` | 抽取置信度，不等于事实真实性 |
| `review_status` | pending / accepted / rejected |

优先抽取相对客观、时间边界较清楚的事实：

- 出生、死亡、婚姻、离婚；
- 入学、毕业、任职、转职、退休；
- 迁移、出国、长期居住地变化；
- 重大疾病、手术、事故；
- 获奖、出版、重大作品、选举或任命；
- 诉讼、犯罪、破产等公开事件；
- 父母、配偶、子女和重要关系。

不建议第一阶段把“性格坚强”“富贵”“命好”等主观描述直接变成标签。这些描述容易把命理结论反向写入因变量，造成循环论证。

## 三、先算什么命理特征

### 可以稳定计算的特征

对 ADB 的完整出生日期和时间，可以先计算：

- 年柱、月柱、日柱、时柱；
- 日主、阴阳、五行分布；
- 天干十神、纳音；
- 地支藏干、合冲刑害等结构特征；
- 大运及大运起始年龄；
- 出生地经纬度、真太阳时修正后的时间差；
- 时刻是否接近子初、时辰边界或整点/半点。

### 需要配置并做稳健性分析的特征

以下不能只生成一个答案，应作为独立配置：

- 真太阳时或标准时；
- 晚子时归当日还是次日；
- 立春还是正月初一作为年界；
- 藏干权重方案；
- 大运顺逆和起运算法。

### 当前不应直接算的情况

- CBDB 没有出生时辰：不能生成可靠时柱和完整四柱；
- 只有出生年份：不能伪造月份、日期和时辰；
- 历史纪年或推定年份：只能保留日期区间，进入历史分层或敏感性分析；
- 事件只有年份：只能使用年份区间，不应当成精确事件日。

## 四、本地模型与线上模型的分工

推荐采用“本地抽取，线上盲检，规则计算”的三层结构：

1. **规则和确定性代码**：处理日期、时间、地点、事件代码、八字和日期区间。这些结果不交给大模型决定。
2. **本地大模型**：从传记中提出候选事实，输出固定 JSON；同时保存原文证据、模型版本和置信度。模型不能直接修改人物主表。
3. **线上大模型**：只对抽样结果做独立复核，检查事实类型、日期区间、证据片段和遗漏，不直接回写生产数据。

建议流程：

```text
原文 → 规则预处理 → 本地模型候选事实 → schema 校验
     → 抽样线上盲检/人工复核 → 接受或驳回 → life_facts
```

线上检验应使用盲样，不能把本地模型的判断一起发给线上模型；否则测到的是复述能力，不是独立校验能力。报告中应记录准确率、日期区间一致率、遗漏率和人工复核一致率。

ADB 原始传记存在许可约束时，不应默认把完整原文发送给线上服务。优先使用本地模型；线上只发送经过授权的公开数据、脱敏片段或由人工确认可以外发的最小证据。

## 六、建议实施顺序

1. 完善 `events_normalized` 的事件类型字典和地点规范化。
2. 对 CBDB 关联事实建立人工抽样审核集。
3. 用本地模型补充复杂传记事实，保留证据片段。
4. 对当前 300 条分层样本做本地抽取、线上盲检和人工金标准复核。
5. 通过一致性评估后，再扩大到 1000 条或全量，不直接把模型输出用于命理统计。

样本生成命令：

```bash
python3 sample_biographies.py --size 300 --seed 20260731
```

输出文件位于 `data/tasks/`（该目录不入 git）：

- `biography_sample_20260731_n300.jsonl`：本地抽取版，含人物元数据，便于回写；
- `biography_blind_20260731_n300.jsonl`：线上盲检版，只含 `task_id` 和传记文本；
- `biography_sample_20260731_n300.manifest.json`：随机种子、分层数量和文件路径。

模型输出必须符合以下结构，事实中的日期只能是精确日期或日期区间：

```json
{
  "task_id": "bio-20260731-300-0001",
  "facts": [
    {
      "fact_type": "career",
      "fact_subtype": "occupation",
      "date_start": "1998-01-01",
      "date_end": "2005-12-31",
      "date_precision": 9,
      "value_text": "担任某大学教授",
      "place": "某地",
      "evidence_text": "原文中的最小证据片段",
      "confidence": 0.85
    }
  ]
}
```

`confidence` 只表示模型抽取把握，不代表事实真实程度；事实是否接受由证据、人工复核和来源质量共同决定。
